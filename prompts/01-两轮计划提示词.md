# 写计划的两轮提示词

**用法**：先发第一轮，等 Agent 回完、你确认理解无误后，再发第二轮。第一轮只对齐方向，不写代码。

### 1. 原版（微信流 iOS 实际用的）

**第一轮：讲清楚产品形态**

```
我们要把微信流做成 iPhone 版，先别写代码，先把方案定下来。

背景：
- 微信流现在有 Mac 版和 Windows 版，核心代码在 macos/Sources/WeChatBridgeCore，iOS 要复用它，不要另写一套。
- 我在真机上测过：微信 iOS 可以「转发 → 合并转发 → 其他应用 → 选择手机中的应用」，把聊天记录导出成一个 ZIP（里面是 聊天记录.txt + 图片、视频、文件）。测试结论在 docs/design/ios-feature-baseline.zh-CN.md，产品设计在 docs/design/ios-relay-v1.zh-CN.md，你先读这两份。

产品形态：iOS 版是一个「中转站」，v1 只做三件事：
1. 收：微信里转发过来，分享扩展把文件存进收件箱，弹个小卡片就回微信，不打断人。
2. 存：App 里按卡片列出来，点开能像微信一样看聊天记录，图片内联显示。
3. 投：挑一批（或者多批合并），选场景，投给 ChatGPT、豆包、千问、WorkBuddy、Claude、DeepSeek、Obsidian、文件夹或者任意 App。

iOS 做不到的事情你要提前标出来，别等写完了才发现：
- 分享扩展不能直接打开别的 App，也不能自动粘贴，最后一下只能让用户在分享面板里点目标。
- 有的 App 不收 ZIP（豆包、千问），要自动改成 聊天记录.txt + 图片。
- 微信一次最多转 100 条，超过的要能分批收、最后合并。

你先跟我确认一下你理解的对不对，有疑问直接列出来问我，不要自己猜。
```

**第二轮：要两份能直接交给 Agent 执行的文档**

```
理解没问题。现在帮我出两份文档，放在 docs/design/ 下：

一、开发技术文档 ios-dev-spec.zh-CN.md
目标是：交给任何一个 Agent，只读这一份加上档期文档，就能把 iOS v1 做完并验证交付。要包含：
- 给执行者的工作规则：只在 .worktrees/ios-relay 里改；每个任务单独提交，标题以 [AI] 开头；不 push；改到 macos/ 必须跑 swift test，Mac 不能退化；做不到验证的写「待真机」，不许标通过。
- 环境前提和怎么检查、怎么补。
- 输入数据规格：微信 iOS 导出的 ZIP 和 TXT 长什么样，图片、表情、链接、视频号的占位写法。
- 架构、目录、工程配置（XcodeGen），所有 Bundle ID、App Group 写死，不要另起名字。
- 每个模块的规格：分享扩展、收件箱、中转站列表、详情、目标能力表、投递规划、投递面板、Obsidian、场景、合并收集、首次引导。
- 验证方法：分模拟器能自动验的（编号 S1、S2…）和必须真机验的（R1、R2…），每条写清楚怎么操作、看到什么才算过。
- 任务清单，按依赖顺序编号，从 T0 排到 T9。
- 交付定义：全部打勾才算 v1 完成。
- 待决问题：需要我回答的列出来，不要自己猜。
- 不在 v1 的东西也写明。

二、档期文档 ios-schedule.zh-CN.md
- 按里程碑拆（M0 环境骨架、M1 收、M2 存、M3 投、M4 知识库与场景、M5 收集打磨、M6 真机验收），每个写工期、日期，以及出口闸门：哪些 S/R 验证和单元测试通过才能进下一个。
- 关键路径，哪些任务可以并行。
- 什么时候需要我亲自做什么（装平台、真机测试、签名账号）。
- 风险和应对。
- 进度汇报格式：每完成一个任务，按固定格式报一次：任务、状态、提交、验证结果、没验证的、下一步、需要我做的。

两份文档里的任务编号、验证编号要对得上。写完我看一遍，没问题就开工。
```
