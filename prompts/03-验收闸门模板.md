# 验收闸门模板

**用法**：每条验收都要写成"一看就知道过没过"的句子。别写"体验要好"，写"做了 X，必须看到 Y"。

```
## 验证方法

### 自动验证（编号 S）
| 编号 | 怎么操作 | 看到什么才算过 |
|---|---|---|
| S1 | 【操作步骤】 | 【可以判断对错的结果】 |
| S2 | 分享一个 0 字节的文件 | 提示失败，不存进去 |
| S3 | 删除一条记录，5 秒内点撤销 | 记录恢复 |
| S4 | 杀掉 App，再分享一次，重新打开 | 能看到新记录 |

### 人工验证（编号 R）
| 编号 | 怎么操作 | 看到什么才算过 |
|---|---|---|
| R1 | 【必须人来做的操作】 | 【结果】 |

## 里程碑出口闸门
| 里程碑 | 要通过的验证 |
|---|---|
| M1 | S1、S2，单元测试全过 |
| M2 | S3、S4 |

## 交付定义（全部打勾才算完成）
- [ ] 所有 S 验证通过
- [ ] 所有 R 验证通过，或标明「待人工」及原因
- [ ] 已有测试 0 失败
- [ ] 验收记录写完：每个问题写清现象、原因、哪次提交修的

## 待决问题（需要我回答，不要自己猜）
| # | 问题 | 影响 | 没有答案时的默认做法 |
|---|---|---|---|
| Q1 | 【问题】 | 【影响哪一步】 | 【它打算怎么做】 |
```
